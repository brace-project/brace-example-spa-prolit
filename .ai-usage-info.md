# AI Usage Info

## Zweck

`brace-example-spa-prolit` is a reference application for Brace plus a Vite/TypeScript SPA built with TrunkJS Prolit. `bootstrap.php` in the repository root is the central project bootstrap, backend code lives under `app.be/`, frontend code under `app.fe/`, and `www/index.php` is only the web front controller.

## Bootstrap and application loading

The root `bootstrap.php` is registered through Composer's `autoload.files`. Brace CLI and the web entrypoint both load Composer first, therefore both use this same bootstrap.

`bootstrap.php` loads `app.be/01_init.php`. That file sets `AppLoader::SetAppRoot(__DIR__)`. The normal numbered Brace application files are then loaded from `app.be/`; `app.be/02_app.php` creates the application and registers its base modules.

## Relevant examples

- `bootstrap.php` — central Composer-loaded entrypoint for CLI and web.
- `app.be/01_init.php` — sets the Brace application root to `app.be/`.
- `app.be/02_app.php` — creates the Brace application and registers base modules.
- `app.be/src/Controller/GreetingController.php` — class-based Brace controller with a `#[BraceRoute]` attribute.
- `app.be/20_routes.php` — controller registration plus `TypeScriptApiStubModule` with automatic generation into `app.fe/src/generated-api.ts`.
- `app.be/10_middleware.php` — `ViteAutoHtml` emits `<tj-responsive><router-content></router-content></tj-responsive>` directly.
- `app.fe/vite.config.ts` — Vite proxy and `vite-plugin-run` hook for `spa-api-build`.
- `app.fe/src/pages/HomePage.ts` — class-based Prolit page with `@route`, generated API client and `scopeResource`.
- `app.fe/src/main.ts` — TrunkJS Router registration and startup; no separate app-shell component.

## Frontend build boundary

`package.json`, `vite.config.ts` and `tsconfig.json` intentionally live under `app.fe/`. Therefore `node_modules`, Vite cache and frontend build output stay inside the frontend application directory. Repository-level PHP tooling is reached through relative paths such as `../vendor/bin/brace`.

## Temporary VCS dependencies

Until the reorganized TrunkJS packages are published, `app.fe/package.json` uses pnpm Git subdirectory dependencies from `trunkjs/trunkjs-monorepo`. The matching Vite and TypeScript aliases intentionally resolve the TypeScript source entrypoints. Replace these Git dependencies and aliases with published package versions once available.

## API generation

Do not add a separate PHP build file or a Brace-specific Vite plugin. Configure the output only in `TypeScriptApiStubModule` and use its registered command:

```bash
vendor/bin/brace spa-api-build
```

The generated `app.fe/src/generated-api.ts` is ignored and must not be edited manually.
