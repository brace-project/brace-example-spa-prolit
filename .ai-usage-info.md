# AI Usage Info

## Zweck

`brace-example-spa-prolit` is a reference application for Brace plus a Vite/TypeScript SPA built with TrunkJS Prolit. `bootstrap.php` in the repository root is the central project bootstrap. Backend source lives under `app.be/`; frontend source lives under `app.fe/`; Node/Vite/TypeScript tooling lives in the repository root.

## Bootstrap and application loading

The root `bootstrap.php` is registered through Composer's `autoload.files`. Brace CLI and the web entrypoint both load Composer first, therefore both use this same bootstrap.

`bootstrap.php` sets `AppLoader::SetAppRoot(__DIR__ . '/app.be')`. Brace then loads the three numbered backend files from `app.be/`: `01_init.php`, `10_middleware.php` and `20_routes.php`.

## Frontend toolchain

- `package.json` — project-level Node dependencies and scripts.
- `tsconfig.json` — TypeScript configuration for `app.fe/src`.
- `vite.config.ts` — Vite root `app.fe`, Brace proxy, package aliases and API-stub build hook.
- `app.fe/src/app.scss` — SCSS source compiled by Vite/Sass.
- `app.fe/dist/` — production frontend bundle.

Vite proxies every request to Brace except Vite-internal paths, frontend source/module paths and requests that address concrete frontend files.

## API-stub generation through brace/mod-spaserve

Do not add a separate generator script or custom API-build implementation.

`app.be/20_routes.php` configures `Brace\SpaServe\Codegen\TypeScriptApiStubModule` and sets the target to `app.fe/src/generated-api.ts`. The module uses `TypeScriptApiStubGenerator`, registers the `spa-api-build` Brace command itself, and can generate automatically in development.

The root `vite.config.ts` invokes:

```bash
vendor/bin/brace spa-api-build
```

through `vite-plugin-run` on Vite startup and before production builds. The root package script `pnpm api:build` invokes the same command explicitly.

The generated `app.fe/src/generated-api.ts` is ignored and must not be edited manually.

## Temporary VCS dependencies

Until the reorganized TrunkJS packages are published, root `package.json` uses pnpm Git subdirectory dependencies from `trunkjs/trunkjs-monorepo`. The matching Vite and TypeScript aliases resolve their TypeScript source entrypoints. Replace these Git dependencies and aliases with published package versions once available.
